# CONTRIBUTING

Как принести свой мод или профиль в lfs-marginalia.

## Главное правило: мод или профиль

- **Мод** (`mods/<книга>/...`) — применяется по инструкции без правок:
  патч, скрипт, портируемый рецепт.
- **Профиль** (`profiles/<машина>/...`) — референс с машинно-зависимыми
  значениями: PARTUUID, разрешение панели, разметка, LOCALVERSION.

В файле есть хоть одно значение, которое у чужой машины будет другим —
это профиль.

## Как добавить мод

1. `cp -r mods/_template mods/<книга>/<глава>-<тема>/<имя-мода>` —
   книга `lfs`/`blfs`, глава `NN-<тема>` по оглавлению соответствующей книги.
2. Положить файлы мода, заполнить `README.md` по шаблону и `mod.yaml`.
3. Обновить сводную таблицу в корневом `README.md`:

   ```bash
   python3 tools/gen-mod-table.py   # печатает таблицу, вставить в README
   ```

4. Если есть скрипты — прогнать `shellcheck`, диагностику писать по-русски
   в `stderr`, патчи применять через `apply.sh` с `--dry-run` и бэкапом
   `.orig`.

## Как добавить профиль

`profiles/<имя-машины>/lfs/`, README по образцу `profiles/thinkpad-x200s/`
с явной пометкой «это референс».

## Процесс

- PR, добавляющий мод или профиль, должен содержать приложенный
  скриншот терминала системы, на которой модификация реально собрана
  и проверена, с выводом:

  ```bash
  echo lfs-marginalia && uname -r
  ```

  Это подтверждение, что изменение собрано руками на живой системе,
  а не сгенерировано наугад. PR без скриншота не принимается.
- Коммиты — на английском, коротко, повелительное наклонение
  («Add GRUB config…»).
- Один PR — один мод/профиль или одна связная правка.
- Если мод проверен на версиях, которых нет в `versions.env` — обновить
  его или указать диапазон в карточке.

## Лицензия

Вкладывая код, вы соглашаетесь на распространение под GPL-2.0
(см. `LICENSE`). Патчи на ядро производны от GPL-кода апстрима и этим
покрыты автоматически.
