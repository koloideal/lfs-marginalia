# lfs-chroot

## Что это и зачем

В главе 7.4 книга требует смонтировать корень будущей системы в `$LFS`,
пробросить туда виртуальные файловые системы (`/dev`, `/dev/pts`, `/proc`,
`/sys`, `/run`, `/dev/shm`) и выполнить `chroot`. До конца сборки входить
в этот chroot приходится десятки раз — и каждый раз по книге это пачка
команд из нескольких разделов, которые приходится помнить или собирать
по закладкам.

Скрипт делает всё за один запуск: находит свободный loop-device,
подключает `lfs.img`, монтирует корень и виртуальные ФС, открывает shell
внутри chroot. При выходе (`exit`/`Ctrl+D`) снимает **только те**
монтирования и loop, которые создал сам; если внутри остаются другие
процессы — честно сообщает и ничего из-под них не отключает.

## Совместимость

- **Версия LFS:** любая — не патч и не сборочный рецепт, а обёртка
  над `mount`/`chroot`.
- **Важно:** скрипт рассчитан на сборку **в raw-образе через loop**. Если
  LFS лежит на реальном разделе (`/dev/sdaX`), скрипт в текущем виде не
  нужен — раздел монтируется как в книге, либо из скрипта убирается часть
  с `losetup`.
- **Разметка образа:** раздел `p1` — swap, `p2` — корень ext4. При другом
  номере корневого раздела меняется строка с `${LOOP}p2`.
- **Пути** заданы в шапке скрипта:

```bash
IMG=/home/lfs-build/lfs.img   # путь к raw-образу
LFS=/mnt/lfs                  # точка монтирования корня
```

## Как применить

```bash
chmod +x lfs-chroot
./lfs-chroot        # при необходимости скрипт сам перезапустится через sudo
```

Внутри открывается root-shell с промптом `(lfs chroot)` и чистым
окружением: `HOME=/root`, `PATH=/usr/bin:/usr/sbin`,
`MAKEFLAGS=-j<число ядер>` — как предписывает книга.

## Как проверить, что сработало

```bash
# внутри chroot:
ls /usr/bin/gcc        # тулчейн LFS виден
mount | grep /proc     # proc смонтирован
```

Промпт `(lfs chroot) root:/#` — вход выполнен.

## Как откатить

`exit`. Скрипт размонтирует за собой и отключит loop-device. Если после
аварийного выхода монтирования остались:

```bash
findmnt -R /mnt/lfs                      # что осталось смонтированным
losetup -j /home/lfs-build/lfs.img       # какой loop держит образ
```

## Заметки

- Повторный запуск при живых loop и монтированиях **переиспользует** их:
  второй chroot откроется рядом, при выходе ничего не сломается.
- Если `$LFS` уже смонтирован с **другого** раздела — скрипт остановится,
  а не перемонтирует.
- `udevadm settle` нужен, чтобы разделы `loopXpN` успели появиться в `/dev`
  до попытки mount.
