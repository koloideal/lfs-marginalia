# AGENTS.md

Правила репозитория для агентов и контрибьюторов.

## Что это за репозиторий

Набор модификаций, патчей и конфигов для сборки Linux From Scratch
(проверено на LFS 13.1, редакция systemd, ядро 7.2.10 — см. `versions.env`).
Целевая машина — ThinkPad X200s, сборка ведётся в raw-образе диска на
хосте Arch Linux.

## Мод vs профиль — главное правило репозитория

| | `mods/` | `profiles/` |
|---|---|---|
| Что | портируемая модификация | конфиги конкретной машины |
| Для чужого юзера | применяется по инструкции без правок | референс: значения подставляются свои |
| Признак | содержит только переносимое | содержит значения, существующие только на конкретном железе/разметке (PARTUUID, разрешение панели, LOCALVERSION, разрешение в grub.cfg) |
| Группировка | по главе книги LFS | по имени машины |

Простой тест при добавлении: в файле есть хоть одно значение, которое у
чужой машины будет другим — это профиль. Применяется буквально — это мод.

## Структура

```
├── versions.env            # версии, на которых всё проверено
├── mods/
│   ├── _template/          # шаблон README нового мода
│   └── <NN>-<тема>/<имя-мода>/   # NN = глава книги LFS
└── profiles/<имя-машины>/  # железо + разметка + конфиги
```

Главы книги для именования `mods/`: `05-toolchain`, `07-chroot`,
`08-packages`, `09-config`, `10-kernel`, `post-install` (новые группы
добавлять по тому же принципу).

## Как добавить мод

1. `cp -r mods/_template mods/<глава>-<тема>/<имя-мода>` и положить файлы
   мода (патч, скрипт, конфиги).
2. Заполнить README по шаблону:
   - загаловок + 1–2 абзаца «что это и зачем» для читателя без контекста;
   - карточка-таблица: этап (глава книги), где выполняется (host/chroot/
     target), на чём проверено, требования, риск, откат;
   - «Применение» — нумерованные шаги строго в порядке выполнения:
     подготовка артефактов → вход в среду → применение → сборка. Шаги
     должны работать, если идти сверху вниз и ничего не знать заранее;
   - «Проверка» — как увидеть, что мод сработал;
   - «Заметки» — совместимость по версиям, подводные камни, связь
     с другими модами.
3. Не дублировать: карточка отвечает «подойдёт ли и когда», тело —
   «как сделать». Одна мысль живёт в одном месте.
4. Если добавляется `apply.sh`: `set -euo pipefail`, проверка предусловий
   (например, что PWD — дерево исходников ядра), `--dry-run` до реального
   применения патча, бэкап заменяемых файлов в `.orig`, диагностика
   по-русски в `stderr`.
5. Добавить строку в сводную таблицу корневого `README.md`.
6. Если мод привязан к версиям, которых нет в `versions.env` — обновить
   его или отметить диапазон в карточке.

## Как добавить профиль

1. `mkdir profiles/<имя-машины>` (нижний регистр, дефисы).
2. Скопировать структуру README из `profiles/thinkpad-x200s/`:
   таблица железа → схема разметки → файлы и куда они ставятся →
   нумерованные шаги адаптации под другую машину.
3. В шапке README профиля явно пометить, что это референс, а не готовое
   решение.

## Стиль

- Вся документация и сообщения скриптов — по-русски, формально, без
  обращения на «ты» (императивы на «-те»: «запустите», либо безличные
  конструкции).
- Без канцелярита и воды: каждая строка несёт факт или действие.
- Коммиты — на английском, коротко, повелительное наклонение
  (формат как в `git log`: «Add GRUB config...»).
- Команды в README дать так, чтобы их можно было скопировать и выполнить;
  рабочую директорию указывать явно.
